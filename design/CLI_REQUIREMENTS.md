# CLI requirements

Requirements for the `thwart` command-line tools: `validate`, `show`, `map`, `search` and `debug`. Owned by thwarter coder. Command-by-command detail, including commands not built yet, is in `design/CLI_DESIGN.md`. RFC 2119 keywords are used as in `REQUIREMENTS.md`.

Split out of `REQUIREMENTS.md` on 2026-11-23. The REQ-CLI ids are stable. A change another component needs here goes to the commander as a message.

## Requirements

- REQ-CLI-1: The binary MUST expose, at minimum, `validate`, `show`, `map`, `search`, and `debug` subcommands.
- REQ-CLI-2: `--world <path>` MUST be available as a global option overriding the configured default world path for that invocation.
- REQ-CLI-3: `validate` MUST load the world and report, at minimum: files that failed to parse, and connections whose target location `id` was never loaded. `validate --strict` MUST additionally check that a character's `default_location` refers to a loaded location.
- REQ-CLI-4: `validate` MUST exit with a non-zero status if any problem was found, and zero otherwise, so it's usable as a CI gate.
- REQ-CLI-5: `show` MUST display the world's summary (REQ-CLI-11) with no argument, or, given a name, that thing (REQ-CLI-9). It MUST error clearly, not silently return nothing, if the name matches nothing in the loaded world.
- REQ-CLI-6: Output MUST support text, JSON, and YAML formats via `--format`, selectable independently per command.
- REQ-CLI-7: A command not yet implemented MUST say so and exit non-zero, and MUST NOT produce output that looks like a real result (a fabricated map, invented search matches, or made-up performance numbers). This requirement exists because the first implementation of this CLI violated it in `map`, `search`, and `debug`; see `CHANGELOG.md` › 0.1.0.
- REQ-CLI-8: `search` is REQ-CLI-18, and `map` is REQ-CLI-17.
- REQ-CLI-9: `show <name>` MUST show any thing: a location, object or character, named by id or by link (REQ-CF-25), in its starting version, or in another with `--state <name>` and `--chapter <name>` (REQ-ENG-15). When a name is the id of more than one kind, `show` MUST say so and take `--kind location|object|character` to choose. The text form is the author's view: a location as the shared room view (REQ-CON-8), an object with its fields and its actions' mechanics (marking an action with no response), a character with where it starts and what it carries, then, for a thing with any, its states (marking the starting and shown one), its chapter versions, and its templates in the order they apply. `--format json` and `yaml` give the version's typed data.
- REQ-CLI-10: `show --template <name>` MUST show a template or built-in (REQ-CF-21) exactly as written, so an author can copy it, and say where it was found (its file, or built in). A bare name is looked up from the world root as REQ-ENG-19 describes; a path from the root finds a template in any scope. An unknown name MUST be an error that lists the templates there are.
- REQ-CLI-11: `show` with no name MUST summarize the world: its `world/` definition (title, author, version, starting room, intro), its story values and player, every chapter with its order, title and scope, and the ids of every location, object and character, sorted. `--format json` and `yaml` MUST give the same as data.
- REQ-CLI-17: `map [location]` MUST draw the world as ASCII from a room (the world's starting room by default), each room a box on a grid cell placed by its compass exits, links drawn between them, doors marked, the room drawn from and rooms not yet written marked, out to `--depth` exits away, and MUST list after the grid every exit that doesn't fit it (up, down, other directions, a cell already taken) as `room: direction → target`. `--output <file>` writes it to a file. The layout MUST be available to the console as plain data, so the console draws it itself.
- REQ-CLI-18: `search <query> [location]` MUST find every location, object, character and door whose id, title or prose (an object's responses included) contains the query, ignoring case unless `--case-sensitive`, or matches it as a regular expression with `--regex`, whose matching MUST run in linear time so no pattern can hang it. `--type location|object|character|door` limits the kinds, and `--type text` matches prose only. A location limits it to rooms in that folder and the things they hold or where characters start. Each match MUST say the thing's kind, id and title, and for a prose match the line it's in. `--missing-connections` MUST instead list every exit to a room not written yet. No matches is not an error.

## Packaging and installing worlds

Specified by the coder and agreed by the commander, 2026-11-23. Covers REQ-CFG-5 and 7, REQ-CFG-8 (checking an archive) and REQ-WS-6.

- REQ-CLI-12: `thwart package` MUST write a world and its persona into one archive (REQ-CFG-7): a zip file named `<persona>-<world>-<version>.thwarter`, which anyone can rename to `.zip` and open without Thwarter (the version from `world/index.md`, left out if it has none), in the current folder or at `--output <path>`. Its layout MUST be:
  - `thwarter-package.toml`, the manifest: `format = 1`, `persona` and `world` (the folder names, which become the install path), the world's `title` and `version`, the `thwart` version that packaged it, and the date;
  - `<persona>/index.md`, the persona file, if the persona has one;
  - `<persona>/<world>/`, the world's files, as they are on disk.
- REQ-CLI-13: A package MUST hold every file in the world folder except what the loader skips (REQ-CF-24: dot names, Hugo's own folders, `world.toml`'s `ignore` list) and `world/styles/`, which is the author's writing aid, not part of the game. `world.toml` ships, since its tool settings are about the world. Author comments ship too, since worlds are readable source and play already hides them; `--strip-comments` removes every `<!-- -->` author comment (but not response markers) from the packaged copies, leaving the author's files untouched. A world that fails `validate` MUST NOT be packaged; warnings don't stop it.
- REQ-CLI-14: Before writing a package, `thwart package` MUST say which of the persona's details ship with it (REQ-WS-6): the pen name and every contact detail, with the file they come from. It MUST also say how many author comments will ship, and in how many files, since authors may leave private notes or spoilers in them. On a terminal it MUST then ask to go on, defaulting to no. `--yes` skips the question; without a terminal and without `--yes` it MUST refuse, so a script never publishes details by accident. The console's `/package` says the same thing (REQ-CON-37).
- REQ-CLI-15: `thwart install <file>` MUST unpack a package into `$XDG_DATA_HOME/thwarter/worlds/<persona>/<world>/` (REQ-CFG-5), with the persona file at `worlds/<persona>/index.md`. It MUST check the archive first and refuse the whole install, writing nothing, if any entry is absolute, holds `..`, is a link, falls outside the layout above, or the archive unpacks to more than 200 MB or 10,000 files. If the world is already installed, it MUST refuse unless given `--replace`, which swaps the new copy in whole (unpacked beside it, then renamed into place) so a failed install leaves the old one as it was. Saves are kept apart (REQ-CFG-6) and survive a replace, reconciled on load as any save is (REQ-ENG-27). The persona file is written if absent, and replaced by the package's copy, with a note, if it differs.
- REQ-CLI-16: `thwart installed` MUST list the installed worlds (persona, world, title, version). `thwart play <persona>/<world>` MUST find an installed world when no such folder exists where it's run, so a player never needs the install path.
